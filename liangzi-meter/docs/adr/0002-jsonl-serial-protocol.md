# ADR-0002：串口协议采用 JSON Lines + hello 握手

- 日期：2026-08-18
- 状态：已接受

## 背景

上位机与设备经 StickS3 原生 USB CDC（硬件 CDC + JTAG，板型默认 `CDCOnBoot=cdc`）通信，`Serial` 直接映射到 USB，无需额外板型配置。需要一套对两端都简单、可人工调试的协议。

## 决策

采用 **JSON Lines**：每行一条 UTF-8 JSON，`\n` 分隔，波特率 115200。消息按 `type` 字段区分，消息集：

| 方向 | 类型 | 说明 |
|---|---|---|
| 上位机 → 固件 | `ping` | 探测设备在线 |
| 固件 → 上位机 | `hello` | 握手：型号、固件版本、协议版本、能力列表、是否已配置 |
| 上位机 → 固件 | `config` | 全量配置快照（WiFi/NTP/API key/峰谷覆盖/提示音/屏幕方向/旋屏开关），整体覆盖 NVS |
| 固件 → 上位机 | `ack` | 对 `config` 的确认（成功/失败 + 原因） |
| 上位机 → 固件 | `get_state` | 请求当前状态快照 |
| 固件 → 上位机 | `state` | 状态上报：时间/峰谷（含 `weekend`、`holiday` 日期标记）/余额/电量/WiFi 状态 |

- 配置为**全量覆盖**语义：每次 `config` 携带全部字段，未携带字段视为清空（或保持默认）。
- `hello` 通过协议版本与能力列表声明可用功能；省电配置使用 `power_saving` 能力标记。新上位机连接不具备该能力的旧固件时禁用相应配置并提示升级，不静默假装配置成功。
- 新固件收到旧上位机消息时，缺失的省电字段采用固件默认值；新 `state` 诊断字段均为可选，上位机缺字段时显示不可用，以保持双向兼容。
- 省电配置保存后立即热应用；需要避让 TLS、声音或串口活动的策略在当前任务结束后切换。固件发送成功 `ack` 后主动补发一次 `state`，供上位机确认实际生效状态。
- 全量配置按原子事务校验：任一已提供字段非法时，固件以失败 `ack` 返回字段与原因，不修改 NVS，也不部分应用；仅兼容旧协议时缺失的新字段采用默认值。
- `config` 消息字段（2026-08-21 增补）：`wifi{ssid,password}` / `ntp` / `api_key` / `balance_warn` / `peak_ranges[]` / `alert_enabled` / `screen_rotation`（0..3，见 ADR-0005）/ `auto_rotate`（bool，见 ADR-0005）。
- `state` 消息字段（2026-08-21 增补）：`rotation`（当前屏幕方向）、`auto_rotate`（旋屏开关回显）。
- API key 以明文 JSON 传输——链路为本地 USB，攻击面可接受（与 ADR-0001 一致）。
- 未知 `type` 的合法 JSON：固件忽略；非法行：固件丢弃并计入日志计数。保证协议演进向前兼容。

## 后果

- **正面**：极简；任何串口终端可人工 `readline` 调试；无二进制帧/校验开销。
- **负面（接受）**：无校验和——USB 链路误码率极低，且 JSON 结构不合法即丢弃，不会误执行。
- **交互流程**：上位机连接 → 发 `ping` → 收到 `hello` → 若有已保存配置则自动下发 `config`（手动按钮兜底）→ 可随时 `get_state` 拉取或等待固件周期 `state`。

## 备选方案

- 二进制帧 + CRC：防错更强但不可人工调试、两端实现成本高，对本地 USB 链路收益不足，弃用。
