# Spec: 提示音功能（alert tones）

Status: resolved

## Problem Statement

桌面摆件 liangzi-meter 目前只有视觉反馈（峰谷颜色、余额红色告警），没有声音。用户希望设备能主动"告诉"他两件关键的事：**进入高峰时段**（开始烧钱）和**高峰期余额在减少**（扣费正在进行）。声音风格沿用 War Thunder RWR 复刻项目（rwr-alert）的「敌跟踪/敌导弹」告警音。

同时要求：功能必须**默认关闭**，由上位机显式开启——开箱安静，不打扰。

## Solution

新增一个**提示音功能（alert tones）**，上位机提供总开关（默认关）。开启后：

- **进入高峰**（非高峰→高峰边沿）：播放**敌跟踪音**一次（高 554.37Hz 215ms + 低 370Hz 215ms ×2 组，约 0.9s，播完自停）。
- **高峰期间余额查询加速**：余额查询间隔从 5 分钟缩短为 **15 秒**；离开高峰恢复 5 分钟。
- **余额减少持续告警**：高峰期间每轮查询，若当前余额 < 上次成功查询余额 − 0.01 元，则**进入持续播放敌导弹音**（高 554.37Hz 83ms + 低 392Hz 83ms ×3 音/组，组间短静音循环，不间歇）；直到某一轮查询判定余额**不再减少**（当前 ≥ 上次）才停止；离开高峰或关闭开关也立即停止。

关闭开关 = 完全保持现状（无任何声音，余额查询恒为 5 分钟）。

## User Stories

1. 作为桌面摆件用户，我想在上位机界面勾选"提示音功能"开关，以便不改代码就能启用声音。
2. 作为桌面摆件用户，我想该开关默认关闭，以便开箱即安静。
3. 作为桌面摆件用户，我想开关状态在固件 NVS 持久化，以便重启设备后保持我的选择。
4. 作为桌面摆件用户，我想进入高峰时段时听到一次敌跟踪提示音，以便耳朵就知道"开始烧钱了"。
5. 作为桌面摆件用户，我想重启后若已身处高峰时段不误播"进入高峰"音，以便不会开机突然响一声。
6. 作为桌面摆件用户，我想高峰期间余额查询频率加快到 15 秒，以便更快感知扣费动作。
7. 作为桌面摆件用户，我想非高峰期间查询频率保持 5 分钟，以便不浪费 API 配额。
8. 作为桌面摆件用户，我想关闭开关后查询频率也保持 5 分钟，以便开关严格等于"保持现状"。
9. 作为桌面摆件用户，我想余额比上次查询减少超过 0.01 元时开始持续播放敌导弹音，以便立即感知正在扣费。
10. 作为桌面摆件用户，我想余额持平或回升（不再减少）时持续告警自动停止，以便不会被无限吵。
11. 作为桌面摆件用户，我想离开高峰时段时持续告警自动停止，以便非高峰保持安静。
12. 作为桌面摆件用户，我想关闭开关时告警立即静音，以便随时手动压制声音。
13. 作为桌面摆件用户，我想不足 0.01 元的小数波动不触发告警，以便避免因舍入误报。
14. 作为桌面摆件用户，我想敌导弹持续告警由多段短促音组成且组间有短停顿，以便声音有节奏、可辨识。
15. 作为桌面摆件用户，我想告警音播放不阻塞显示刷新/串口/网络，以便响铃期间设备一切功能正常。
16. 作为上位机用户，我想设备状态回显里看到开关当前值，以便确认下发是否生效。
17. 作为上位机用户，我想旧固件收到含新字段的配置时忽略该字段，以便协议向后兼容。
18. 作为开发者，我想告警音逻辑是纯状态机（可独立验证），以便编译冒烟即覆盖核心判定。

## Implementation Decisions

### 总开关

- 配置项 `alert_enabled`（bool，默认 `false`）：上位机可配、固件 NVS 持久化、串口 `config` 消息携带、`state` 消息回显。
- 语义：**严格等于"保持现状"**。关闭时固件不播放任何音，余额查询间隔恒为默认 5 分钟。
- 向后兼容：固件解析 `config` 时缺失该字段视为 `false`；旧固件忽略未知字段（协议现有规则）。

### 告警音播放器（非阻塞）

- 两种模式：
  - **一次性**（敌跟踪）：播完固定组数自动停。
  - **持续**（敌导弹）：循环播放直到显式 `stopAlert()`。
- 实现为 loop tick 驱动的状态机（`alertTick()` 每轮调用），**不建 FreeRTOS task、不阻塞主循环**——与 liangzi-meter 现有"显示/串口/网络同一 loop 推进"的架构一致。
- 音量固定 96/255（电池供电安全音量，沿用 rwr-alert 移植值）。

### 余额对比状态机（访谈确定的语义）

每轮**成功**查询后执行（prototype 期间与用户确认的口径）：

```
prev = lastBalance
lastBalance = current
若 开启 && 高峰 && prev ≥ 0:
    current < prev - 0.01 且未在告警 → 进入持续敌导弹音
    在告警 且 current ≥ prev（不再减少）     → 停止
否则（关闭/非高峰）且在告警 → 停止
```

- 对比基准 = **上次成功查询值**（无论是否高峰都更新 `lastBalance`）。
- "不再减少" = 当前值 ≥ 上次值（含持平）。
- 持续告警播放期间没有固定轮间间隔——**连续循环**，直到判定停止。

### 高峰检测

- 边沿触发：仅"非高峰 → 高峰"翻转时播敌跟踪音；上电首帧不触发（先建立基线再比较）。
- 高峰期间查询间隔 15 秒的判断与显示共用同一峰谷判定（`inPeakWindow`），不引入第二套时钟。

### 停止条件汇总（持续告警）

| 条件 | 动作 |
|---|---|
| 某轮查询判定余额不再减少 | 停止 |
| 离开高峰时段 | 停止 |
| 开关关闭 | 立即停止 |

## Testing Decisions

- 本仓库无单测/CI，验证方式为**编译冒烟 + 真机清单**（AGENTS.md 约定）。
- **Seam（与用户确认中）**：
  1. 固件侧——告警状态机收敛为纯逻辑：输入（开关、峰谷、当前/上次余额）→ 输出（播放/停止/查询间隔），编译冒烟覆盖。
  2. 协议侧——host `config` 消息含 `alert_enabled` 且固件 `ack`；`state` 回显与配置一致。
- 真机清单：开关开/关、进入高峰响一声、高峰 15s 查询（观察日志频率）、余额减少持续响、余额回升停止、关开关立即静音。

## Out of Scope

- 音量/音色可配置（写死 96 与 RWR 原始频率）。
- 除"进入高峰"外的其他一次性提示（如离开高峰、同步成功、按键反馈）。
- 非高峰期间的余额减少告警。
- host 端对告警状态的可视化（仅配置开关 + 状态回显）。

## Further Notes

- 音调数据源：rwr-alert 移植（`liangzi-meter` 同工作区项目，见 rwr-alert/sticks3）。
- 展示文案与协议字段：协议字段用 `alert_enabled`（英文标识），文案「提示音功能」仅出现在 host UI。
