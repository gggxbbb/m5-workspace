# Spec: 分供电状态的可配置省电策略

Status: ready-for-agent

## Problem Statement

liangzi-meter 当前以固定亮度持续点亮屏幕，WiFi 长期保持活跃，处理器主循环没有空闲省电策略，IMU、扬声器等外设也未按实际功能需求管理。设备在电池供电时续航偏短，在 USB 供电时也存在不必要的功耗与温升。

用户希望在不牺牲峰谷判断、余额查询、提示音告警、USB 配置和即时交互的前提下优化功耗。设备用户具备硬件经验，因此省电行为不能只做成不可调整的固定策略；外接供电和电池供电均需提供充分的亮度、显示、唤醒、WiFi 与处理器策略配置，并且必须能观察实际生效状态。

## Solution

为设备增加一套按供电来源工作的省电状态机。外接供电时屏幕保持可见，但仍可启用 WiFi 与处理器空闲省电，以降低功耗和温升；电池供电时可按配置从正常亮度进入低亮度，再进入熄屏监控。熄屏不会停止峰谷判断、余额查询或声音告警。

省电配置由上位机分页展示并以全量配置快照下发，包含三档亮度、两个显示超时、唤醒来源、拿起灵敏度，以及外接/电池两套 WiFi 和处理器省电开关。设备通过版本与能力协商声明支持情况，原子校验配置，热应用成功后主动回传实际状态。

本方案采用联网待机、modem sleep、处理器动态空闲/浅睡和外设按需供电，不采用会中断后台监控的 deep sleep 或 PMIC 关机。真实功耗由用户使用外部测量设备验证；软件只负责提供确定行为和可观测诊断。

## User Stories

1. 作为设备用户，我想分别配置 USB 供电和电池供电的正常亮度，以便兼顾桌面观感与移动续航。
2. 作为设备用户，我想单独配置电池低亮度，以便控制变暗阶段的可读性与功耗。
3. 作为设备用户，我想电池供电时在无人操作后自动变暗，以便减少不必要的背光耗电。
4. 作为设备用户，我想电池供电时在更长时间无人操作后自动熄屏，以便获得更明显的省电收益。
5. 作为设备用户，我想分别配置变暗等待时间和熄屏等待时间，以便适配桌面、随身携带等不同使用场景。
6. 作为设备用户，我想将变暗设置为“永不”，同时仍可单独启用熄屏，以便直接从正常亮度进入熄屏。
7. 作为设备用户，我想将熄屏设置为“永不”，以便设备只降低亮度但持续可见。
8. 作为设备用户，我想拥有电池省电总开关，以便一键恢复电池常亮行为进行比较或调试。
9. 作为设备用户，我想关闭总开关时仍使用电池亮度配置，以便亮度选择不被省电状态机覆盖。
10. 作为设备用户，我想熄屏后仍继续峰谷判断，以便设备不会错过时段切换。
11. 作为设备用户，我想熄屏后仍继续余额查询，以便重新查看时余额不是长期过期值。
12. 作为设备用户，我想熄屏后仍保留高峰提示与余额下降告警，以便设备继续履行监控职责。
13. 作为设备用户，我想任意设备按键始终能够唤醒屏幕，以便任何配置组合都不会造成永久黑屏。
14. 作为设备用户，我想熄屏后的第一次 KEY1 或 KEY2 只唤醒屏幕，以便看不见界面时不会误刷新或误切页。
15. 作为设备用户，我想低亮度状态下按键既恢复正常亮度又执行原功能，以便可见界面仍保持直接交互。
16. 作为设备用户，我想拿起设备即可唤醒屏幕，以便不必先寻找按键。
17. 作为设备用户，我想拿起唤醒与自动旋屏相互独立，以便固定方向时仍可使用自然唤醒。
18. 作为设备用户，我想开关拿起唤醒，以便避免运输、震动桌面等场景中的误唤醒。
19. 作为高级用户，我想配置拿起动作的运动阈值、持续时间与防重复时间，以便针对实际环境调校灵敏度。
20. 作为设备用户，我想余额下降告警可以选择是否点亮屏幕，以便在声音之外获得视觉反馈。
21. 作为设备用户，我想告警唤屏复用普通无人操作计时，以便所有唤醒行为遵循同一套变暗与熄屏规则。
22. 作为设备用户，我想进入高峰的普通提示音不自动点亮屏幕，以便固定时段事件不会额外消耗背光电量。
23. 作为设备用户，我想插入 USB 时设备立即唤醒并使用外接供电亮度，以便桌面使用恢复持续可见。
24. 作为设备用户，我想拔出 USB 后从电池正常亮度重新开始无人操作计时，以便设备不会刚拔线就立刻变暗或熄屏。
25. 作为高级用户，我想分别控制外接供电时的 WiFi 省电和处理器空闲省电，以便优化桌面使用的功耗与温度。
26. 作为高级用户，我想分别控制电池供电时的 WiFi 省电和处理器浅睡，以便按场景选择续航与响应速度。
27. 作为上位机用户，我想所有高级省电开关彼此独立，以便关闭某种运行时优化时不影响显示策略。
28. 作为设备用户，我想 WiFi 省电时仍保持关联，以便手动刷新和后台查询不必等待重新入网。
29. 作为设备用户，我想外接供电的处理器省电不能破坏 USB 串口响应，以便上位机始终可靠连接。
30. 作为设备用户，我想自动旋屏和拿起唤醒都关闭时完全停用 IMU，以便未使用的传感器不继续耗电。
31. 作为设备用户，我想只启用拿起唤醒时让 IMU 使用低功耗运动检测，以便无需处理器持续轮询。
32. 作为设备用户，我想没有声音任务时关闭扬声器输出与功放，以便声音功能不会产生持续静态耗电。
33. 作为设备用户，我想麦克风保持关闭，以便未使用的录音硬件不消耗电力。
34. 作为上位机用户，我想通过常亮、均衡和省电预设快速填充配置，以便从合理组合开始调校。
35. 作为高级用户，我想选择预设后仍能修改所有字段，以便预设不会限制完整配置能力。
36. 作为上位机用户，我想预设只填充表单、不会自动下发，以便检查后再决定是否改变设备。
37. 作为上位机用户，我想一键恢复默认省电配置，以便从异常组合快速回到已知基线。
38. 作为上位机用户，我想在独立分页中管理显示、唤醒和高级省电配置，以便大量选项不会挤坏现有窗口。
39. 作为上位机用户，我想设备状态和串口日志在所有配置分页中持续可见，以便调参时即时观察结果。
40. 作为上位机用户，我想看到当前供电来源，以便确认设备选用了哪套策略。
41. 作为上位机用户，我想看到正常、低亮度或熄屏的实际显示阶段，以便确认超时状态机正在工作。
42. 作为上位机用户，我想看到当前实际亮度，以便区分配置值与设备当前输出。
43. 作为上位机用户，我想看到 WiFi 与处理器省电是否实际生效，以便发现被活动任务暂时阻止的情况。
44. 作为上位机用户，我想看到 IMU 当前处于关闭、运动检测还是自动旋屏模式，以便确认外设按需管理。
45. 作为上位机用户，我想看到电池电压与估算电量，以便结合外部测量观察趋势。
46. 作为上位机用户，我想新上位机连接旧固件时明确提示不支持省电配置，以便不会误以为下发已经生效。
47. 作为旧上位机用户，我想新固件继续接受缺少省电字段的旧配置，以便升级固件后基本功能仍可使用。
48. 作为上位机用户，我想非法配置被整体拒绝并指出具体字段，以便界面值、NVS 和运行状态不会部分分叉。
49. 作为上位机用户，我想配置成功后立即收到实际状态，以便现场调节亮度和灵敏度。
50. 作为开发者，我想省电行为集中在一个确定性状态机中，以便用事件序列覆盖主要边界而不依赖真实等待。
51. 作为开发者，我想硬件相关动作与策略判定分离，以便在不连接设备时验证绝大多数行为。
52. 作为维护者，我想真实功耗测量留给外部仪表，以便固件不增加不可靠的自测功能或额外耗电。

## Implementation Decisions

### 省电策略模型

- 建立单一的省电策略状态机，输入至少包括：供电来源、配置快照、当前显示阶段、最后活动时间、按键事件、拿起事件、余额下降事件、USB 插拔事件、自动旋屏状态，以及网络、串口、声音和显示任务是否繁忙。
- 状态机输出包括：显示阶段、目标亮度、是否消费按键、WiFi 省电请求、处理器省电请求、IMU 模式、扬声器/功放需求和是否需要整帧重绘。
- 显示阶段为“正常”“低亮度”“熄屏”。外接供电始终处于正常显示阶段；电池供电由总开关及两个超时控制。
- 任何按键、拿起事件或启用中的余额下降告警唤屏均重新开始无人操作计时。普通网络活动、时间刷新、状态上报和峰谷切换不属于用户活动。
- 熄屏状态的首次 KEY1/KEY2 事件由状态机消费；低亮度状态的按键不被消费。
- 插入 USB 立即进入外接正常亮度；拔出 USB 进入电池正常亮度并清零无人操作时长。

### 配置模型与默认值

- 省电配置具备总开关，并分别保存外接供电亮度、电池正常亮度、电池低亮度、变暗等待时间、熄屏等待时间、拿起唤醒开关、告警唤屏开关、拿起运动阈值、持续时间、防重复时间，以及外接/电池两套 WiFi 和处理器省电开关。
- 默认配置：总开关开启；外接供电亮度 `160`；电池正常亮度 `96`；电池低亮度 `24`；30 秒变暗；2 分钟熄屏；拿起唤醒和告警唤屏开启；四个运行时省电开关全部开启。
- 超时值 `0` 表示“永不”。当两个超时均为有限值时，熄屏时间必须严格晚于变暗时间；变暗为“永不”时仍允许独立配置熄屏。
- 正常亮度与低亮度使用产品级 `1..255` 范围；低亮度不强制小于电池正常亮度，但上位机应提示反常组合而非擅自改值。
- 拿起灵敏度使用物理语义参数，不暴露 BMI270 原始寄存器。初始默认建议为运动阈值 `200 mg`、持续时间 `200 ms`、防重复时间 `3000 ms`，最终默认值与安全范围须通过真机校准确认 `[需真机]`。
- 旧 NVS 中不存在的新字段使用上述默认值；升级不要求用户重新下发配置。
- 预设是上位机表单行为，不是持久化枚举。常亮预设使用默认亮度、两个超时均为“永不”且保留运行时省电；均衡预设等于默认配置；省电预设使用外接亮度 `160`、电池正常亮度 `64`、电池低亮度 `8`、15 秒变暗和 60 秒熄屏，其余省电功能保持开启。所有预设填充后仍可编辑。

### 供电来源与显示

- 供电来源依据 M5PM1 实际电源来源或 VBUS 状态判定，不以“正在充电”代替“USB 已接入”；满电但仍接 USB 的设备必须继续属于外接供电模式。
- 背光关闭只改变显示可见性，不停止时间、峰谷、余额或告警任务。熄屏期间跳过不必要的 framebuffer 更新；任何唤醒都强制整帧重绘。
- 亮度和超时配置热应用。改变当前供电来源对应的亮度时立即生效；改变超时时从配置应用时重新计时。

### WiFi 与处理器省电

- WiFi 第一阶段始终保持关联，只在配置允许时启用 modem sleep。周期性彻底关闭 WiFi 不属于本规格。
- 外接供电与电池供电分别拥有 WiFi 省电开关。
- 外接供电的处理器策略使用不会中断 USB CDC 的保守空闲省电；电池供电可使用更深入的浅睡，但必须能被按键、IMU 运动、必要定时器和当前后台职责唤醒。
- 外接供电与电池供电分别拥有处理器省电开关。CPU 频率等底层参数不暴露给上位机。
- 网络 TLS、声音播放、串口收发、显示更新或其他进行中的任务可以暂时阻止处理器进入省电状态；任务结束后自动恢复配置策略。
- 不使用 ESP32 deep sleep，也不使用 M5PM1 定时关机。若未来增加极限续航模式，必须作为具有不同监控语义的独立设计。

### 外设按需供电

- 自动旋屏启用时，IMU 保持满足旋屏采样需要的工作模式。
- 自动旋屏关闭但拿起唤醒开启时，IMU 使用 BMI270 低功耗运动检测和中断，不以主循环高频轮询替代。
- 自动旋屏与拿起唤醒均关闭时停用 IMU。
- 扬声器与功放仅在声音状态机需要播放时启用，播放完成后关闭；提示音功能关闭时不得保留静态声音输出。
- 麦克风始终关闭。扬声器与麦克风互斥规则继续遵守。

### 串口协议与兼容

- `hello` 增加整数协议版本与能力列表。现有无版本握手视为协议 v1；本功能使用新的协议版本并声明 `power_saving` 能力。
- 省电配置以结构化对象随全量 `config` 快照传输，避免继续增加大量无分组顶层字段。字段分为亮度、超时、唤醒与运行时策略四组。
- 新上位机连接不具备 `power_saving` 能力的旧固件时，禁用相关页面并显示升级提示，不发送设备无法理解的省电配置。
- 新固件接收旧协议配置时，对缺失的省电对象使用默认配置；已有 WiFi、API key、峰谷等字段继续正常应用。
- 固件必须先把整个配置解析到候选快照并完整校验。任一已提供字段非法时返回失败 `ack`，包含字段标识与原因，不修改 NVS，不改变当前运行状态。
- 配置通过校验后整体持久化并热应用。需要避让活动任务的无线、处理器或声音策略可延迟到任务结束，但 `ack` 必须明确表示已经接受并保存。
- 成功 `ack` 后固件主动发送一次 `state`。新增诊断字段均为可选字段，旧上位机可以忽略，新上位机缺字段时显示“不可用”。
- `state` 新增实际供电来源、显示阶段、实际亮度、WiFi 省电生效状态、处理器省电生效状态、IMU 模式、电池电压与估算电量。

### 上位机信息架构

- 配置界面改为分页，不在现有单页窗口继续纵向堆叠。
- 页面至少分为“连接与账户”“显示与交互”“高级省电”。设备状态和串口日志位于公共区域，切换配置页时保持可见。
- 显示与交互页包含三档亮度、两个超时、省电总开关、拿起唤醒和告警唤屏。
- 高级省电页包含两种供电状态下的 WiFi/处理器开关，以及拿起灵敏度参数。
- 提供常亮、均衡、省电三个预设和恢复默认值操作。选择预设只修改表单，不自动保存或发送。
- 表单在本地进行与固件相同的范围及交叉字段校验；固件仍是最终校验者。
- 本地配置存储继续保存完整快照。读取旧配置时补充省电默认值，写回时保留全部新字段。

## Testing Decisions

- 好测试验证用户可观察的状态转换与协议结果，不断言具体计时器、寄存器调用次数或内部类结构。
- 最高层自动化接缝是确定性的省电策略状态机。测试以虚拟时间、供电来源、配置和事件序列作为输入，断言显示阶段、目标亮度、按键消费、唤醒、WiFi/CPU 请求与外设模式输出。硬件调用只执行状态机输出，不参与策略判断。
- 状态机至少覆盖：USB 常亮；拔线后重新计时；正常→低亮度→熄屏；两个“永不”组合；总开关关闭；熄屏按键被消费；低亮度按键执行；拿起唤醒；拿起关闭；告警唤屏；峰谷切换不唤屏；配置热应用；计时绕回。
- 协议契约测试覆盖：v1/v2 `hello`；能力存在与缺失；旧配置补默认；完整新配置往返；非法单字段与跨字段约束整体拒绝；成功 `ack` 后 `state`；可选诊断字段缺失。
- 上位机测试覆盖：旧本地配置迁移；三个预设只填表不发送；分页字段映射；不支持能力时禁用；错误字段定位；诊断状态渲染。
- 固件最低验证为 `m5stack:esp32:m5stack_sticks3` 编译通过。项目没有现成自动化固件测试框架，因此实现应优先把纯策略逻辑放到可由本机测试驱动的独立接缝，再保留 Arduino 编译冒烟。
- `[需真机]` 验证 USB 插拔后的亮度和计时、KEY1/KEY2 熄屏消费行为、低亮度交互、余额告警唤屏、峰谷提示不唤屏、USB CDC 在外接 CPU 省电时持续可用。
- `[需真机]` 验证 WiFi modem sleep 下连接稳定、5 分钟余额查询和高峰 15 秒监控不丢失、手动刷新响应正常。
- `[需真机]` 验证 BMI270 三种模式切换、拿起运动中断、灵敏度范围、误触发、防重复时间，以及自动旋屏关闭时拿起仍可唤醒。
- `[需真机]` 验证无声音时扬声器/功放关闭、提示音开始前正确启用、结束后关闭，且不违反 Speaker/Mic 互斥约束。
- 真实电流、温升和续航由用户使用外部测量设备进行同场景改造前后对比；自动化测试不声明固定节电百分比或固定续航时长。

## Out of Scope

- ESP32 deep sleep、M5PM1 定时关机或冷启动式定时唤醒。
- 非高峰时主动断开 WiFi、查询前重新入网的激进无线策略。
- 固定续航时长、固定节电比例或温度下降幅度承诺。
- 内置电流测量、功耗测试模式、外部仪表集成或自动生成测量报告。
- 允许用户直接配置 CPU 频率、BMI270 原始寄存器或 M5PM1 电源轨等可能破坏稳定性的底层参数。
- 改变余额查询周期、峰谷判断、提示音音色或余额下降判定语义。
- 新增极限续航模式；若未来需要，应单独访谈并记录其暂停后台监控的产品语义。

## Further Notes

- 目标设备为 M5StickS3（K150），FQBN `m5stack:esp32:m5stack_sticks3`，M5Stack ESP32 core 3.3.8。
- StickS3 使用 M5PM1，不得移植 AXP192/AXP2101 示例。电源来源、电池电压及基础电源控制参考 `kb/lib-m5pm1.md` 的“API 重叠区”和“电源状态”。
- 睡眠与定时唤醒能力边界参考 `kb/demos-sticks3.md` 的“睡眠唤醒”与 `kb/lib-m5unified.md` 的 Power API；本规格明确不采用 PMIC 关机路径。
- loop 仍必须持续满足 `M5.update()` 的按键刷新要求。任何处理器省电实现都必须通过定时唤醒或等价调度保证按键与后台状态机正确推进。
- 已接受的领域词汇记录在 `CONTEXT.md`；联网待机取舍记录在 ADR-0006；协议版本、能力协商、原子配置与热应用时序记录在 ADR-0002。
- 本规格只定义待实施工作，当前未开始固件或上位机实现。
